SQL
¿Qué es?
Structured Query Language. 
Lenguaje estándar para consultar y 
manipular bases de datos 
relacionales. Permite extraer, filtrar, 
agrupar y transformar datos 
almacenados en tablas.
¿Para qué sirve?
Es la primera capa de acceso a los 
datos transaccionales. Toda 
organización con un sistema de 
ventas tiene una base de datos 
SQL detrás.
En nuestro caso
Cada vez que un cliente pasa un 
producto por la caja en 
Corporación Favorita, esa venta 
queda registrada en una base de 
datos SQL. Es el punto de origen 
del dato — antes de que viaje por 
el pipeline, al Data Lake, y 
finalmente al modelo construido 
con Python y pandas.
Ya lo conoces — aquí lo ubicamos en el flujo completo. CONCEPTO CLAVE
Pipeline de Datos
¿Qué es?
Secuencia automatizada de pasos 
que mueve, transforma y entrega 
datos desde una fuente hasta un 
destino. Cada paso del pipeline 
toma el resultado del anterior y lo 
prepara para el siguiente.
¿Para qué sirve?
Garantiza que los datos lleguen 
limpios, completos y a tiempo al 
lugar donde serán analizados o 
procesados por un modelo. Sin 
pipeline, los datos quedan 
atrapados en su origen.
En nuestro caso
El dato de la venta de leche en 
Costanera no llega solo al modelo 
de predicción. Pasa por un 
pipeline: se extrae de SQL, se 
limpia, se transforma, se carga al 
Data Lake y se procesa con Spark. 
Si un paso falla, la cadena se 
rompe. CONCEPTO CLAVE
Data Lake
¿Qué es?
Repositorio centralizado que 
almacena grandes volúmenes de 
datos en su formato original — 
estructurados, semiestructurados y 
no estructurados — sin necesidad 
de definir su estructura de 
antemano.
¿Para qué sirve?
Permite acumular datos de 
múltiples fuentes (ventas, clima, 
inventario, redes sociales) sin 
transformarlos primero. La 
transformación ocurre cuando se 
necesita, no al momento de 
almacenar.
En nuestro caso
Todas las ventas de las 54 tiendas 
de Corporación Favorita, los datos 
de clima, los calendarios de 
feriados y los registros de 
inventario convergen en un Data 
Lake. Desde ahí, el pipeline los 
entrega listos para ser procesados 
con Python y pandas (polars) y 
alimentar el modelo de predicción. Del código de barras al cliente satisfecho

Big Data
¿Qué es?
Conjunto de datos cuyo volumen, 
velocidad o variedad supera la 
capacidad de las herramientas 
tradicionales de procesamiento. No 
es solo "mucho dato" — es dato 
que no cabe en una hoja de 
cálculo ni en un servidor 
convencional.
¿Para qué sirve?
Permite almacenar, procesar y 
analizar información a una escala 
que sería imposible con bases de 
datos relacionales clásicas.
En nuestro caso
El supermercado genera millones 
de registros de ventas, inventario y 
comportamiento de clientes cada 
día. Eso es Big Data: demasiado 
para Excel, demasiado para un solo 
servidor, pero perfectamente 
manejable con las herramientas 
correctas.

Proceso de examinar datos para

CONCEPTO CLAVE
Una componente principal NO representa un producto.
Representa un patrón de comportamiento.
PC1 = 0.18 × Producto A
    + 0.07 × Producto B
    − 0.11 × Producto C
    + 0.04 × Producto D
    + ... (5,000 productos)
        
No es un producto
Ningún componente equivale a un SKU individual.
Es una combinación
Mezcla miles de productos con pesos positivos y negativos.
Es un patrón
PC1 podría representar 'tiendas que venden más en temporada 
alta'.
Una componente principal = un patrón de comportamiento, 
no un producto. ¿Por qué debemos escalar los datos?
EL PROBLEMA DEL ESCALAMIENTO
Producto A
Ventas: 0 – 10 unidades
Producto B
Ventas: 0 – 10,000 unidades
Sin escalamiento → Producto B domina el análisis, ignorando el Producto A
StandardScaler
Transforma cada variable a media = 0 y desviación estándar = 
1.
Todas las variables tienen igual importancia antes de PCA.
Sin escalamiento, PCA mide magnitud — no varianza.

ENTRENAMIENTO
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.ensemble import RandomForestClassifier
import joblib
# 1. Escalar los datos
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
# 2. Aplicar PCA
pca = PCA(n_components=50)
X_train_pca = pca.fit_transform(X_train_scaled)
# 3. Entrenar el modelo
model = RandomForestClassifier()
model.fit(X_train_pca, y_train)
# 4. Guardar los 3 objetos
joblib.dump(scaler, 'scaler.pkl')
joblib.dump(pca,    'pca.pkl')
joblib.dump(model,  'model.pkl')
        
PREDICCIÓN EN PRODUCCIÓN
import joblib
# 1. Cargar los 3 objetos guardados
scaler = joblib.load('scaler.pkl')
pca    = joblib.load('pca.pkl')
model  = joblib.load('model.pkl')
# 2. Nuevo registro con 5,000 variables
X_nuevo = obtener_nuevo_registro()
# 3. Aplicar el MISMO scaler del entrenamiento
X_scaled = scaler.transform(X_nuevo)
# 4. Aplicar el MISMO PCA del entrenamiento
X_pca = pca.transform(X_scaled)
# 5. Predecir
prediccion = model.predict(X_pca)
        
⚠ Nunca uses fit_transform() en producción. Usa siempre transform() — el scaler y el PCA ya fueron ajustados durante el entrenamiento. 
Aplicar fit_transform() sobre datos nuevos recalcularía los parámetros y corrompería la predicción.
Regla de oro
fit_transform() → solo en entrenamiento · transform() → siempre en producción PCA en un Pipeline de Machine Learning

POR QUÉ LA REPRESENTACIÓN NO ES SUFICIENTE
Tenemos una excelente representación para Machine Learning. Pero todavía no podemos comprender visualmente cómo se organizan las

LO QUE NECESITAMOS
Una proyección
Reducir 5,000 dimensiones a 2, conservando la estructura de los

Que preserve vecindades
Las tiendas similares deben aparecer cerca en el mapa. Las

Que sea interpretable
El resultado debe poder leerse visualmente sin conocer las 5,000

REDUCCIÓN DE DIMENSIONALIDAD — SIN MATEMÁTICAS
t-SNE construye una representación bidimensional que intenta conservar las relaciones de vecindad entre observaciones similares.
En nuestro caso, t-SNE toma la matriz de 2,322 tiendas-semanas × 5,000 productos y produce un mapa en 2 dimensiones donde:
Tiendas similares aparecen cerca
Si dos tiendas tienen patrones de venta parecidos en los 5,000 productos, t-SNE las coloca próximas en el mapa.
Tiendas distintas aparecen lejos
Si dos tiendas tienen comportamientos muy diferentes, t-SNE las separa en el espacio bidimensional.
La similitud se mide en 5,000 dimensiones
t-SNE calcula las distancias en el espacio original de alta dimensionalidad, no en el mapa final.
t-SNE no explica las variables. Revela la estructura. Visualización t-SNE del Caso

ERRORES FRECUENTES AL INTERPRETAR UN MAPA T-SNE
❌ Los ejes no tienen significado físico
Las dimensiones t-SNE no representan variables del negocio, 
productos ni componentes principales. Son únicamente 
coordenadas utilizadas para construir la visualización.
❌ No interpretar las distancias globales
La separación entre regiones lejanas no representa una medida 
cuantitativa exacta de diferencia. t-SNE preserva principalmente 
las relaciones locales entre observaciones.
✅ Lo realmente importante
Interpreta únicamente las vecindades locales: los puntos 
cercanos suelen representar observaciones con patrones de 
venta similares.
t-SNE es una herramienta de exploración visual. Su objetivo es 
facilitar el descubrimiento de estructuras y patrones en datos de 
alta dimensionalidad, no proporcionar una representación 
geométrica exacta del espacio original de los datos.
 Lo que NO debemos interpretar
LIMITACIONES DEL MAPA T-SNE
t-SNE es una herramienta poderosa, pero sus resultados pueden inducir a error si no se conocen sus limitaciones.
INTERPRETACIONES INCORRECTAS
Los ejes no tienen significado físico
El eje X y el eje Y no representan variables del negocio. No tienen 
unidades ni interpretación directa.
Las distancias globales pueden ser engañosas
Dos grupos que parecen cercanos en el mapa pueden estar muy 
lejos en el espacio original de 5,000 dimensiones.
El tamaño de un grupo no implica importancia
Un grupo grande no necesariamente representa más tiendas o 
más ventas. Depende de los parámetros del algoritmo.
REGLA DE ORO
t-SNE es una herramienta de exploración, no de 
confirmación.
Úsalo para generar hipótesis
El mapa sugiere estructura. La estructura debe validarse con 
análisis adicionales.
No uses t-SNE para medir distancias
Las distancias en el mapa 2D no son métricas confiables del 
espacio original.
Los resultados dependen de los parámetros
Cambiar la perplejidad (perplexity) puede producir mapas 
visualmente muy diferentes. PCA y t-SNE

REDUCCIÓN DE DIMENSIONALIDAD — INTUICIÓN PRÁCTICA
UMAP (Uniform Manifold Approximation and Projection) es una técnica moderna de reducción de dimensionalidad no lineal que transforma 
datos con miles de variables en una representación de pocas dimensiones, preservando la estructura de los datos tanto a nivel local como, en 
gran medida, a nivel global.
Fue desarrollada para ofrecer una alternativa más rápida y escalable que t-SNE, manteniendo una excelente capacidad para visualizar patrones 
complejos en grandes volúmenes de datos.
EL FLUJO DE UMAP
Datos originales
El punto de partida: la matriz de alta dimensionalidad.
Grafo de vecinos
UMAP construye un grafo conectando cada observación 
con sus vecinos más cercanos.
Optimización
El algoritmo ajusta una representación de baja 
dimensión que respeta ese grafo.
Representación en 2D
El resultado: un mapa donde la estructura del 
espacio original se conserva.
¿POR QUÉ UMAP?
✓  Reducción no lineal
Captura estructuras complejas que métodos lineales como PCA 
no pueden representar.
✓  Preserva estructura local y global
Mantiene vecindades locales y, en mayor medida que t-SNE, la 
estructura global.
✓  Velocidad superior
Considerablemente más rápido que t-SNE en datasets grandes.
✓  Escalable
Diseñado para funcionar bien con millones de observaciones.
✓  Versátil
Puede usarse para visualización y como preprocesamiento para 
modelos.
UMAP busca representar los datos en dos dimensiones manteniendo, en la medida de lo posible, la forma y organización del espacio 
original.

ERRORES FRECUENTES AL INTERPRETAR UN MAPA UMAP
❌ Los ejes no tienen significado físico
Los ejes UMAP 1 y UMAP 2 son dimensiones construidas por el 
algoritmo. No representan variables originales del conjunto de 
datos ni tienen una interpretación de negocio directa.
❌ No interpretar las distancias globales como 
medidas exactas
Aunque UMAP preserva mejor la estructura global que t-SNE, 
las distancias entre grupos alejados no representan una medida 
exacta de similitud. El análisis debe centrarse en la organización 
general y en las relaciones entre observaciones cercanas.
✅ Lo realmente importante
Utilice UMAP para descubrir patrones, identificar agrupaciones, 
detectar anomalías y comprender mejor la organización general 
de los datos antes de construir modelos predictivos.
UMAP es una herramienta de exploración visual. Su principal 
objetivo es facilitar la comprensión de la estructura de datos de 
alta dimensionalidad, no medir distancias exactas.

Accuracy
% total de aciertos. ✔ Útil cuando las clases están 
balanceadas.
Precision
Cuando predice Sí, ¿acierta? ✔ Importante cuando un 
falso positivo es costoso — fraude, spam.
Recall
¿Cuántos positivos reales encontró? ✔ Importante 
cuando un falso negativo es costoso — diagnóstico 
médico, alertas críticas.
F1-score
Media armónica de Precision y Recall. ✔ Útil cuando 
ambas métricas son igualmente importantes.

Métricas de Evaluación para Clasificación
En problemas de clasificación, el desempeño del modelo no se evalúa mediante MAE, RMSE o R², sino utilizando métricas derivadas de la Matriz de Confusión.
Accuracy
% total de predicciones correctas. Usar cuando las clases están 
balanceadas.
Precision
De las predicciones positivas, ¿cuántas eran realmente positivas? 
Alta Precision = pocos falsos positivos.
Recall
De todos los casos positivos reales, ¿cuántos detectó el modelo? 
Alto Recall = pocos falsos negativos.
F1-score
Media armónica de Precision y Recall. Usar cuando se necesita 
equilibrio entre ambas.

PUNTO RUIDO DBSCAN · PARÁMETROS
DBSCAN (Density-Based Spatial Clustering of Applications with Noise) es un algoritmo de clustering que agrupa puntos según su densidad en 
el espacio: forma clusters donde hay muchos puntos cercanos entre sí, y marca como ruido (anomalías) los puntos aislados. A diferencia de K-
Means, no requiere definir el número de grupos de antemano.
El parámetro eps
eps
RADIO DE BÚSQUEDA
eps define el radio máximo de vecindad: la distancia máxima que puede haber entre dos puntos para que se consideren vecinos. Si un punto 
tiene al menos min_samples vecinos dentro de ese radio eps, se convierte en un punto núcleo (core point) y forma parte de un cluster.
eps pequeño eps grande DBSCAN · PARÁMETROS
El parámetro min_samples
min_samples
VECINOS MÍNIMOS
min_samples define el número mínimo de puntos que deben estar dentro del radio eps para que un punto sea considerado un punto núcleo 
(core point). Si un punto tiene al menos min_samples vecinos dentro de su radio eps, forma parte de un cluster; si tiene menos vecinos, se 
clasifica como un punto borde (border point) o como ruido. Valores altos de min_samples exigen una mayor densidad local para formar clusters.
min_samples pequeño min_samples grande DBSCAN · FUNCIONAMIENTO

¿Qué es MLOps?
MLOps (Machine Learning Operations) es el conjunto de prácticas que permiten desarrollar, desplegar, monitorear y mantener modelos 
de Machine Learning de forma confiable, automatizada y reproducible.
MLOps surge de la necesidad de aplicar principios de ingeniería de software al ciclo de vida completo de los modelos de Machine Learning.

El riesgo de memorizar
Un modelo que memoriza los datos

Generalización
La capacidad de un modelo para desempeñarse bien sobre datos nuevos se 
llama generalización. Es el criterio más importante para evaluar un modelo. GENERALIZACIÓN · DEFINICIÓN
¿Qué es la generalización?
Definición formal
La generalización es la capacidad de 
un modelo entrenado para producir 
predicciones correctas sobre datos 
nuevos que no formaron parte del 
conjunto de entrenamiento.
Ejemplo sencillo
Un modelo entrenado para detectar 
spam con correos de 2020 debe 
seguir funcionando correctamente 
con correos de 2024, aunque el 
lenguaje y los patrones hayan 
cambiado.
Idea clave
Un modelo que generaliza bien no memoriza: aprende la estructura subyacente 
de los datos. La diferencia entre memorizar y aprender es la esencia del 
Machine Learning. GENERALIZACIÓN · DIAGNÓSTICO

¿Qué es la Validación Cruzada?
Definición
La validación cruzada consiste en repetir varias veces el 
entrenamiento y la evaluación utilizando diferentes particiones 
del conjunto de datos.
Objetivo
Su objetivo no es mejorar el modelo, sino obtener una 
estimación más confiable de su capacidad de generalización.
Múltiples evaluaciones
Se entrena y evalúa el modelo varias veces 
con distintas particiones
Estimación robusta
El promedio de los resultados es más 
representativo que una única medición
Reducción de variabilidad
Disminuye el impacto de una partición 
desfavorable VALIDACIÓN CRUZADA · K-FOLD
K-Fold Cross Validation
El conjunto de datos se divide en K partes iguales (folds). En cada iteración, un fold diferente actúa como conjunto de validación mientras los

Cada fold actúa exactamente una vez como conjunto de validación. El resultado final es el promedio de las K evaluaciones. K-FOLD · PROCESO PASO A PASO
¿Cómo funciona?
Dividir los datos
Separar el conjunto en K folds de igual tamaño
Entrenar el modelo
Usar K-1 folds como conjunto de entrenamiento
Evaluar
Medir el desempeño sobre el fold reservado
Cambiar Fold
Seleccionar el siguiente fold como validación
Repetir el proceso
Completar las K iteraciones
Calcular el promedio
Promediar los K resultados para la estimación final
El proceso garantiza que cada observación del conjunto de datos sea utilizada exactamente una vez como dato de validación. K-FOLD · INTERPRETACIÓN DE RESULTADOS
